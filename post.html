🚀 Just shipped something I'm genuinely proud of — a full-stack cloud file storage system built from scratch.

I've been building backend systems for a while now, but this project hit differently. I wanted to understand what actually happens when you click "Upload" on Google Drive — not just at the surface level, but every single step: auth, file routing, cloud storage, and secure retrieval. So I built my own version of it.

Meet CloudVault — a Google Drive-inspired backend built with Node.js, Express, MongoDB, and AWS S3. Users can register, log in, upload files to the cloud, and download them securely — all with proper auth and authorization checks.

🔐
JWT Auth + Cookies Stateless authentication using signed tokens stored in HTTP cookies.
☁️
AWS S3 Storage Files go directly from Multer to S3 — zero disk usage on the server.
🔗
Signed Download URLs Time-limited pre-signed S3 URLs — files expire in 60 seconds after generation.
🛡️
Authorization Guards Users can only access their own files — enforced at the database query level.
🗄️
MongoDB Metadata File keys, original names, and user references stored in Mongoose schemas.
🎨
EJS + Tailwind UI Server-side rendered views with a clean drag-and-drop upload interface.
Tech Stack
Node.js Express.js MongoDB Mongoose AWS S3 AWS SDK v3 multer-s3 JWT bcrypt EJS Tailwind CSS express-validator
What I actually learned building this 🧠
  • How multer-s3 streams files directly to S3 without touching local disk — this is huge for scalability
  • Pre-signed URLs are a brilliant pattern: your server never serves the file, S3 does — reduces load massively
  • Separating auth (who are you?) from authorization (is this file yours?) is a subtle but critical design decision
  • Storing only the S3 key in MongoDB — not the full URL — keeps your storage layer swappable
  • Cookie-based JWT feels simple but has real security nuance: httpOnly, expiry, and secret management matter

The part I'm most proud of? The download flow. When a user hits /download/:key, the server first checks MongoDB to confirm the file belongs to that user, then generates a fresh pre-signed URL from S3 and immediately redirects to it. Clean, secure, and the server never touches the file bytes.

If you're learning backend development, building a file storage system is one of the best projects you can do. It forces you to think about auth, cloud services, database design, and security all at once — not in isolation.
